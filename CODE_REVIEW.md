# Code Review — universal_dub

Дата: 2026-10-15. Ревью всего трекаемого кода (`universal_dub.py` 1269 строк,
`webui.py` 214 строк, тесты, вспомогательные скрипты) + верификация:
`pytest tests/` (11 passed), `py_compile`, сверка всех голосов Edge-TTS с живым
списком `edge-tts 7.2.8` (`list_voices()`).

## Вердикт

Архитектура пайплайна здоровая: чистые стадии (extract → whisper → diarization →
MT → TTS → merge), корректные fallback-цепочки (GPU→CPU, Qwen→Edge, batch→per-segment),
resume по артефактам, защита от «разбежавшегося» TTS. Главное слабое место —
**реестр голосов Edge-TTS**: половина записей была битой (несуществующие имена),
что для 12 из 30 языков-фолбэка ломало озвучку или гендер. Исправлено и проверено
против живого API.

## Найдено и исправлено (в этом коммите)

### Критические

1. **Битые имена голосов Edge-TTS (9 языков из 30).** Проверено живым
   `list_voices()`: `uk-UA-PavloNeural`, `sv-SE-SveaNeural`, `el-GR-AlexiaNeural`,
   `ro-RO-VladuNeural`, `pt-BR-ThelmaNeural`, `nl-NL-XeniaNeural`,
   `hu-HU-TamásNeural` (с акцентом — не существует), `fa-IR-FaridehNeural` —
   не существуют. Для `th` и `fa` мужской/женский голос были одним и тем же
   женским голосом (гендерная диаризация терялась). Исправлено на реальные:
   Ostap/Sofie/Athina/Emil/Francisca/Fenna/Noemi/Farid+Dilara/Niwat.
   После фикса — автопроверка: `BAD VOICES: none`.

2. **EdgeTTS писал MP3 в файл с расширением `.wav`.** `edge_tts.Communicate.save()`
   всегда пишет MP3; пайплайн читает TTS-файлы через stdlib `wave`
   (`_tts_duration_bad`, `merge_tts_segments`) — для Edge валидация длительности
   молча не работала, а merge ловил исключение и подставлял `tts_dur = 1.0`,
   из-за чего темп atempo считался неверно для ВСЕХ сегментов Edge.
   Исправлено: явная конвертация mp3 → wav 24 kHz mono через ffmpeg.
   Примечание: при проверке живой синтез Edge отдаёт `403 WSServerHandshakeError`
   (Microsoft блокирует consumer-эндпоинт; `list_voices` работает) — это внешняя
   проблема edge-tts, не кода; см. «Осталось».

3. **`bench_translate.py` / `bench_rename_me.txt` были синтаксически битыми**
   (обрывок diff-вывода вместо кода, `SyntaxError`). Удалены; в README не
   упоминались, нигде не импортировались.

### Средние

4. **`test_webui_e2e.py` не соответствовал API webui**: передавал 10 аргументов
   вместо 13 (webui ждёт ещё male/female voice и resume_dir) → падение при
   первом же запуске. Переписан, порядок аргументов сверен с `run_btn.click`,
   добавлен `sys.exit` по результату.

5. **Web UI: гонка очереди между заданиями.** Если клиент отключался посреди
   задания, воркер-поток (daemon) продолжал писать в общий `_q`; следующее
   задание получало чужие `done`/`error` события. Добавлен drain очереди перед
   стартом задания. (Полное решение — per-job токен; см. «Осталось».)

6. **Мёртвая ветка в `has_target_script`**: второй `if tl == "ja"` был
   недостижим (первый `in ("zh", "ja")` перехватывал раньше) — для японского
   каны без кандзи («かなだけ») считались «не целевым скриптом» и перевод
   откатывался к оригиналу. Удалена; теперь любое zh/ja-сообщение с CJK
   проходит. (Осознанный компромисс: чистая кана без кандзи по-прежнему
   не проходит — узкий кейс.)

7. **Дублирующая инициализация `ok = fail = 0; t0 = ...`** в `generate_all_tts`
   до и после batch-фазы — первая была мёртвой. Удалена.

### Мелочи / принято к сведению (не изменено)

- `EDGE_VOICES` для неизвестного языка даёт `en`-голоса, но `run_pipeline`
  для edge переопределяет пару на `en-US-GuyNeural/AriaNeural` — два разных
  дефолта для одного случая (безопасно, но несогласованно).
- `Sapi5TTS` принимает `output_path` как есть; `pyttsx3` на Windows требует
  абсолютный путь — при относительном пути тихо не работает. Крайний фолбэк.
- `merge_tts_segments`: при `orig <= 0.05` сегмент пропускается ПОСЛЕ
  инкремента `done_merge` — безвредно.
- `webui.bat` жёстко прописывает `C:\work\universal_dub` — ок для личного
  воркфлоу, не переносимо.
- `DEFAULT_HY_MT_MODEL` указывает на `G:\work\hermes\...` — машинно-зависимый
  путь; при отсутствии модели есть корректный fallback «перевод как есть».

## Раунд 2: сверка со вторым ревью-агентом (2026-10-15)

Параллельный агент ревьюил ту же версию. Результаты пересеклись частично —
он не увидел мои фиксы раунда 1 (читал старые снапшоты файлов) и принёс
несколько новых находок. Итог сверки:

### Согласен и исправлено (раунд 2)
- **`keep-original-audio` миксил оригинал на `volume=0%`** — чекбокс был
  декоративным. Теперь `35%` (регресс-тест).
- **`_tts_duration_bad` на AND-логике** пропускал «разбегание» 15–60 с на
  длинных сегментах. Новая логика: `>60 s` ИЛИ (`>3x` И `>5 s`) — закрывает
  средний диапазон, не флагая легитимный перевод 1.6–2x (тесты на 4 границы).
- **ffmpeg stretch без проверки returncode** — при падении atempo merge читал
  несуществующий/битый файл. Фолбэк перекодирует без фильтра на целевой sr
  (слепая копия, как предлагал второй агент, играла бы с неверной скоростью
  при sr(TTS) ≠ sr(merge) — мой вариант корректнее).
- **Мусор в репо**: 4 галлюцинированных «аудит-отчёта» + PROPOSAL.md
  (заявляли, что universal_dub.py — «бинарный блоб», содержали вставленный
  tool_call XML и пути с именем пользователя в публичном репо) — удалены.
- **Сбор pytest**: корневые `test_*.py` при `pytest` импортировали torch/
  chatterbox и долбились в живой сервер (3 collection errors, 54 с).
  Перенесены в `scripts/` — `pytest` теперь зелёный из коробки.
- **Жёсткие пути** — ENV-оверрайды `UD_FFMPEG` / `UD_SOX_DIR` / `UD_HY_MT_MODEL`.

### Спорно / отклонено с обоснованием
- **«Секретов нет»** — согласен, независимо подтвердил `git grep` по HEAD.
- **«Hy-MT молча фолбэкается в оригинал»** — преувеличение: ветка логирует
  WARN (`Hy-MT model not found ... using source text as-is`). Поведение
  оставлено как осознанный design-decision, ENV-оверрайд пути добавлен.
- **«.git 966 МБ — критично»** — раздувание локальное (dangling Cline-чекпоинты),
  на GitHub не попало (блобы недостижимы из веток). Лечится `git gc --prune=now`
  — выполнено в этом раунде.
- **Edge-голоса** — его «подозрения» (Thelma/Xenia/Vladu/Alexia/Pavlo) я уже
  исправил и верифицировал живым `list_voices()` в раунде 1; он видел старые
  снапшоты. Расхождение файлов он сам объяснил параллельным редактированием.
